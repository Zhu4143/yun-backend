# 2026-10-02 嘴部对齐与播客回复修复

## 1. 说话时嘴部错位

修改文件：`src/avatar/portraitSpeech.js`、`src/avatar/portraitSpeech.test.js`。

原实现将不同视频帧的矩形嘴部贴图直接放到目标嘴部颜色中心，没有保留源贴图的实际中心偏移、倾斜角度或目标尺寸。人物动作改变时可能出现错位；定位失败时还会在固定位置放置嘴部。

现在保留源嘴型的亚像素中心与角度，按目标嘴部的位移、倾斜和尺寸做变换，双线性采样；定位不可靠时保留原视频，不生成悬空嘴。没有改人物画面尺寸、粒子数量、唱片转换或身体动作编排。

验证：新增倾斜回归在修复前失败；修复后嘴型、位移/缩放、定位丢失、静音/结束和采样生命周期测试 7/7。人物动作 23/23、Worker 背压 5/5、音频计量 4/4 通过。

临时验证页面实际扫描说话视频 74 个嘴型帧，并在 wake/listening/speaking 三段原视频上使用真实 TTS 播放。17.8 秒播报累计 5199 次目标嘴部采样均定位成功（这是定位统计，不代表逐帧视觉人工验收）。连续截图确认发声时嘴部随不同头部姿势对齐；完整粒子页面的实际试听出现张嘴，SPEAKING 后回到 LISTENING。截图保存于本地 visualization 目录：`mouth-aligned-open-2.png`、`particle-mouth-aligned-4.png`。仍为音频驱动的开合，不是音素级口型。

## 2. DeepSeek 不回应 / 只报歌名

修改文件：`server.js`、`server/podcastReactionPolicy.js`、`server/podcastReactionPolicy.test.js`、`src/hooks/useYunChat.js`、`src/api/songReactionApi.js`、`src/api/songReactionApi.test.js`。

明确证据：修复前实际 `/api/song-reaction` 请求 long 段落，仅得到固定报歌名。临时诊断显示模型 `deepseek-v4-pro`、`finish_reason=length`、`completion_tokens=140`、`reasoning_tokens=140`，正文为空。原额度被推理全部消耗；固定报歌名掩盖了失败。

此外原播客总策略要求默认 0–1 句、自动切歌通常安静，与主持人提示冲突；后处理硬截为两句 56 字；重复改写也要求两句或空白；前端自动切歌设 75 秒不播报间隔，普通播客没有强制语音，而“自动朗读”当前关闭。这些均是明确的抑制路径。

修复：播客模型额度 4096，短/中/长回复指导分别约 35–70 / 90–150 / 160–240 字；保留完整句子而非按字符截断。随机长度覆盖普通播客和陪伴续播，去掉自动播客 75 秒静默门槛。修正重复改写规则，空正文或额度耗尽明确报错，不伪装成生成成功。播客主动启动 TTS、压低音乐至 0.16，并使用现有 voiceBoost。旧歌曲迟到回复或用户中断不再启动播报；退出播客时也丢弃迟到回复。请求等待上限 45 秒，取消会传递给底层 fetch。生成/播放失败在聊天中显示原因。

验证：同一真实 long 请求修复后返回 109 字、四句评论，约 4.7 秒；验证页多次真实生成后合成并播放，17.8 秒和 12.0 秒音频均正常结束并闭嘴。完整页面换歌得到多句评论，声音面板自动朗读关闭时播客仍运行。没有用静态模板作为成功兜底。

回复长度/推理额度测试 2/2，歌曲反应 API 与取消测试 2/2，基础请求取消/超时测试 2/2，长短随机选择 1/1 通过。定向 ESLint、`node --check server.js` 与 production build 通过。没有模拟网络断线或逐个验证所有上游服务故障；失败提示路径有代码检查与请求取消/超时回归。
